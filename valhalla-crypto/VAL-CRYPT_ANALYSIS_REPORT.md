### 设计理念

Val-Crypt 基于 Valhalla 项目中的 **MeshBrain 认知网络系统**，将神经网络的状态传播机制应用于加密领域：

```
传统加密: 数学运算 (置换、替换、异或)
Val-Crypt: 认知状态传播 (膜状态、网络连接度、智能级别)
```

```
┌─────────────────────────────────────────────────────────────────┐
│                    Val-Crypt 加密流程                           │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  明文字节 [B₀, B₁, B₂, ..., Bₙ]                                  │
│      │                                                          │
│      ▼                                                          │
│  ┌───────────────────────────────────────────────────────────┐  │
│  │              密钥初始化                                    │  │
│  │  membrane_state = key[0]                                  │  │

│  │  fluctuation_intensity = 0.3                              │  │
│  └───────────────────────────────────────────────────────────┘  │
│      │                                                          │
│      ▼                                                          │
│  ┌───────────────────────────────────────────────────────────┐  │
│  │  For each byte Bᵢ:                                        │  │
│  │                                                           │  │
│  │  1. 计算智能级别:                                          │  │
│  │     intelligence = (Bᵢ / 255) × fluctuation_intensity     │  │
│  │                                                           │  │
│  │  2. 确定信号类型:                                          │  │
│  │     signal_type = (intelligence > 0.5) ? 1 : 0            │  │
│  │                                                           │  │
│  │  3. 计算连接因子:                                          │  │
│  │     connectivity = (network_density × 255) + key[i%len]   │  │
│  │                                                           │  │
│  │  4. 综合变换:                                              │  │
│  │     Cᵢ = Bᵢ + membrane_state + connectivity               │  │
│  │          ⊕ (signal_type × 0x5A)                           │  │
│  │          ⊕ key[i % key_len]                               │  │
│  │                                                           │  │
│  │  5. 更新膜状态:                                            │  │
│  │     membrane_state = Cᵢ + key[i % key_len]                │  │
│  └───────────────────────────────────────────────────────────┘  │
│      │                                                          │
│      ▼                                                          │
│  密文字节 [C₀, C₁, C₂, ..., Cₙ]                                  │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 详细对比: Val-Crypt vs AES-256-GCM

| 方面 | Val-Crypt | AES-256-GCM |
|------|-----------|-------------|
| **设计理念** | 神经网络状态传播 | 替换-置换网络 (SPN) |
| **密钥调度** | 简单派生 | 复杂扩展 |
| **块大小** | 流式处理 | 128 bits |
| **认证** | 未内置 | GHASH (内置) |
| **标准化** | 新颖实验性 | NIST FIPS 197 |
| **硬件加速** | 无 (纯 CPU) | AES-NI 指令集 |
| **抗量子** | 未知 | 易受攻击 |
| **实现复杂度** | 低 | 高 |
| **依赖** | 无 | 通常需要库 |

| 方面 | Val-Crypt | ChaCha20-Poly1305 |
|------|-----------|-------------------|
| **设计理念** | 认知状态 | ARX 运算 (加-旋转-异或) |
| **状态大小** | 1 字节膜状态 | 512-bit 块 |
| **轮数** | 1 (默认) | 20 轮 |
| **Nonce 需求** | 无 | 96-bit nonce |
| **认证** | 未内置 | Poly1305 |
| **侧信道抗性** | 中等 | 强 |
| **性能** | 快速 | 非常快 |
| **流行度** | 新 | TLS 1.3 标准 |

### 2️⃣ 协议层面改进

```rust
// 推荐: Encrypt-then-MAC 模式
fn secure_encrypt(data: &[u8], key: &[u8]) -> Vec<u8> {
    let ciphertext = val_crypt::encrypt(data, key);
    let mac = hmac_sha256(&ciphertext, key);
    [ciphertext, mac].concat()
}

// 推荐: 与 AES-GCM 分层
fn layered_encrypt(data: &[u8], key: &[u8]) -> Vec<u8> {
    let layer1 = val_crypt::encrypt(data, key);    // 内层: Val-Crypt
    let layer2 = aes_gcm::encrypt(&layer1, key);   // 外层: AES-GCM
    layer2
}
```

### 3️⃣ 运维层面改进

| 改进项 | 具体措施 |
|--------|----------|
| **密钥轮换** | 每 N 次加密后轮换密钥 |
| **密钥存储** | 使用 HSM 或安全飞地 |
| **输入验证** | 验证和清理输入数据 |
| **速率限制** | 限制解密尝试次数 |
| **审计日志** | 记录加密操作 |

### 4️⃣ 安全加固

```rust
// 内存清零
use zeroize::Zeroize;

fn secure_operation(data: &[u8], key: &[u8]) -> Vec<u8> {
    let mut key_copy = key.to_vec();
    let result = val_crypt::encrypt(data, &key_copy);
    key_copy.zeroize();  // 使用后清零
    result
}

// 常量时间比较
use subtle::ConstantTimeEq;

    computed.ct_eq(expected).into()
}
```

### ✅ 推荐使用场景

| 场景 | 说明 | 安全级别 |
|------|------|----------|
| **数据混淆** | 隐私保护、日志脱敏 | 中 |
| **日志加密** | 运维日志保护 | 中 |
| **配置保护** | 配置文件加密 | 中 |
| **临时数据** | 缓存、临时文件 | 中 |
| **纵深防御** | 多层加密的内层 | 中-高 |
| **研究教育** | 密码学学习 | N/A |

### ⚠️ 谨慎使用场景

| 场景 | 需要添加 | 原因 |
|------|----------|------|
| API 密钥存储 | HMAC 认证 | 防止篡改 |
| 会话令牌 | Nonce | 防止重放攻击 |
| 服务间通信 | 认证 + TLS | 防止中间人 |

### ❌ 不推荐场景

| 场景 | 推荐替代 | 原因 |
|------|----------|------|
| 金融交易 | AES-GCM | 需要审计认证 |
| 医疗数据 | AES-GCM | HIPAA 合规要求 |
| 政府/军事 | FIPS 认证算法 | 法规要求 |
| 密码存储 | Argon2/bcrypt | 需要密码哈希 |
| TLS 替代 | 标准 TLS | 协议复杂性 |
