# Valhalla 全流程运行方法（巩固版，2026-11-01）

程式：`manifestsys/hub-f64/src/bin/valhalla_full_flow.rs`
一条链：**入口（Fate 自动分割）→ 体内（身体周期）→ 出口（原生回应 + 结构问答）**。
本文件是运行说明；证据口径见 `EVIDENCE_MAP_20261101.md`（A 磐石 / D 禁声称），
逐轮记录见 `TEST_RUNS_20261101.md`。

## 设计分账（哪部分是谁的）

| 环节 | 来源 | 说明 |
|---|---|---|
| 入口切分 | **原版设计** | Stem/Tile 的 `receive_data`：容器只收集，Fate 用自身簇方程判收敛、命中收口成段。段长由方程与料的统计形态决定，喂方不预设粒度（证据 A15） |
| 存储记账 | 铁律 2 | 原始字节全量入双侧四元（BlackHole/MeshBrain/MultiNova/BaseForce，Tile 与 Stem 各存一份）。自然料按 8KB 流块、事实按条；**出生切分与存储粒度脱钩** |
| 体内节律 | 原版周期 | 每轮喂料后跑身体周期：tile/stem 周期 → 全局 Fate `tick` → Stem 场沉降 → Tile `propagate`，与训练器同节律 |
| 出口 A 回应 | 本程式（只记录） | 留出料（训练从未喂的尾段）逐字节入场，看 Fate 如何切分、回应形态不设限 |
| 出口 B 问答 | harness 读身体 | 训练期喂过的符号链，测试期问**未喂过的传递问题**；存储通道 = 四元字节抽边限步可达，网络通道 = Tile/Stem 自发连接限步可达（符号→单位映射用喂事实时的段级出生记账）。真题/假题分开报，假题对率塌陷即枢纽污染信号 |
| 出口 C 问答 | **对外 Fate（本日定稿）** | `react`（今晨提交 `bbea60a`）才是问答接口：喂事实时同字节双写全球 Fate 的 `data_store`（主线喂法此前只写四元、`data_store` 恒空，react 无话可送——缺的是这步接线，本程式补上）。测试期每跳调一次 react、解析其送出原文中的边。react 为 `&self` 只读：刺激不入内部 Fate、不 tick、不改方程，纪律由签名保证 |
| 未纳入 | — | vent 式 Fate 抓取出口未接（D11 未立）；巩固只接已证正确的件 |

限定（读数时勿忘）：
- 出生位置是方程公式直写输入统计量，场空间分带是**直接映射不是涌现**（A15 限定语）。
- 符号→单位记账是"段尾窗口"近似：一段可跨多个事实对，该段会同时挂上这些符号，可能形成枢纽捷径；假题对率就是为暴露它而设。
- 双层切分历史上逐块同步（两层 Fate 被全局同步），双层分工未立。

## 运行

```powershell
# 冒烟（2 轮，验证全链通）
$env:VH_ROUNDS="2"; .\target\release\valhalla_full_flow.exe 2>$null

# 正式（20 轮，第 10 / 20 轮各测一次出口）
Remove-Item Env:VH_ROUNDS -ErrorAction SilentlyContinue
.\target\release\valhalla_full_flow.exe 2>$null
```

环境变量：

| 变量 | 默认 | 含义 |
|---|---|---|
| `VH_ROUNDS` | 20 | 总轮数（出口在第 10 轮与末轮测） |
| `VH_CHUNK_KB` | 128 | 每轮每料喂入 KB（四料轮转偏移取新料） |
| `VH_CYCLES` | 2 | 每轮身体周期数 |
| `VH_SEED` | 7 | 事实顺序与假题抽样种子（确定性可复跑） |

料源（只读，不改）：多语文本/代码/图片（`C:\Windows\Web\Wallpaper\Windows\*.jpg`）/
声音（`C:\Windows\Media\Alarm0*.wav`）各留最后 128KB 作回应留出段，训练轮不碰。
符号事实：200 链 × 6 符号（链连写成文本流，相邻对 1000 条在第 1 轮
先于自然料整批喂完——实测在自然料之后喂时 Stem 零收口测不到；
其后各轮纯自然料，问答读"事实结构被冲洗与否"）；
测试题为链内距离 2–5 传递对（真题）与跨链对（假题），训练从未喂过。
规模定标实测：事实流 ~1KB 时 Fate 零出生（自然段长数百至数千字节），
事实总量必须达到段长量级以上才有单位可测——这是入口的已测性质。

## 输出读法

```
料源: 多语文本 xKB / 代码 xKB / 图片 xKB / 声音 xKB
第 N 轮 tiles T cells C stem_links L 存储 S 方程 0.aaaa x²+...
    本轮新生段（stem/tile）: 多语文本 a/b · 代码 c/d · 图片 e/f · 声音 g/h
[第10轮] 结构问答 真题/假题对: 存储 s1/s2 | Tile网络 t1/t2 | Stem网络 u1/u2（题量 Q，符号映射 tile X 符号 stem Y 符号）
[第10轮] 对外Fate问答(react) 真题/假题对: r1/r2（真题首跳沉默 n，react 覆盖符号 M，data_store K 条）
[回应·多语文本] 留出 128KB -> Fate 切 stem n 段（均 m）tile k 段
终局 ...
```

- **新生段数**：Fate 对该料的切分密度；按料分化 = A15 复现。
- **存储**：应精确 = 累计喂入字节 / 8192 × 8（自然料）+ 事实条数 × 8；
  对不上即四元记账破裂，先停查账。
- **方程**：全局簇方程漂移轨迹；只记不判（漂移本身不是智能的证据）。
- **问答读法**：真题率高且假题也"高对"才算结构成立；真题低 = 传递结构
  没进网络/存储；假题对率塌 = 枢纽捷径污染（映射太粗或存储边跨链误连）。
- **react 读法**：首跳沉默 = 接口对该刺激无原文可送（无话，不是答错）；
  react 只送原文、跳步串联在调用侧——"身体经接口送出原文"成立，
  "身体自己做传递推理"不成立，勿混。本程式只把事实双写
  `data_store`（自然料只入四元+分割），这是接线范围非接口上限。
- **第 10 vs 20 轮对照**：读"多训十轮混合自然料，事实结构是保是洗"——
  存储通道应恒定（只增不删），网络通道若被冲洗会掉分。

## 判据（预先声明，跑后不改）

1. 全链无崩、无维度爆炸（入口走 `receive_data` 路径，维度恒 4；若出现
   维度增长即偏离设计，停）。
2. 存储记账精确对账（上式）。
3. Fate 切分按料分化（各料段数/均段长不同量级或明显有别）。
4. 问答：至少一条通道真题 > 假题对率所允许的偶然水平且假题对率不塌；
   全通道真题 ≈ 0 则记"此入口下事实结构未立"，不粉饰。
